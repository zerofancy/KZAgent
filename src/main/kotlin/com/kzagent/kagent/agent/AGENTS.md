# Agent Loop 开发约定

## 上下文缓存

- 修改 Agent loop 或模型请求消息结构时，必须优先保持从第 0 个 token 开始的稳定前缀。LLM 上下文缓存通常按前缀匹配；在历史消息之前插入、删除或修改动态内容，会使其后的整段会话历史无法复用缓存。
- 基础系统提示词和已经产生的历史消息属于稳定前缀。配额警告、Todo reminder、临时状态等可能出现或消失的运行时提示，不得放在基础系统提示词与历史消息之间。
- 动态运行时提示应插入到本轮最后一条 `User` 消息之前，使之前的完整会话保持可缓存，同时维持当前用户请求位于提示之后。
- 插入提示时不得拆开 `Assistant(tool_calls)` 与其对应的全部 `Tool` results。并行工具结果必须继续紧邻发起调用的 Assistant 消息。
- 如果新增的动态信息无法放在当前用户消息之前，应明确评估缓存损失，并选择只影响当前轮、不会破坏既有历史前缀的位置。

## 验证要求

- 修改消息拼接顺序时，为“无动态提示”和“有动态提示”两种请求补充测试，确认基础系统提示词及之前的完整对话是相同前缀。
- 测试必须覆盖包含 tool call/result 的当前轮，确认动态提示不会插入工具调用序列内部。
- 修改缓存相关行为后运行完整的 `./gradlew test`。
