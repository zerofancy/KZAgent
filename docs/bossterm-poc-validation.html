BossTerm PoC 与会话面板接入

结论：通过本机适配层 PoC，已接入底部终端。

选用 BossTerm 1.2.183 的公开 ProperTerminal、TerminalSessionStack 和 TerminalSessionEngine，KZAgent 自行拥有会话、进程与生命周期。没有修改或 fork 上游源码，没有把终端交给 Agent 控制。

原高层 EmbeddableTerminal 没有通过菜单与清理门槛：它追加安装菜单，默认关闭还会留下忽略 HUP 的后台子进程。PoC 保留这两个负例；日志中的基线 FAIL 是预期观察结果，不能解释成原组件通过了验收。

1 · 版本与路线

项目最终选择与证据
Kotlin / JVM编译插件保持 Kotlin 2.4.0，目标 JVM 17，实际解析 kotlin-stdlib 2.4.20；无需跳过 metadata 校验。原 Compose 1.11.1 插件的独立 PoC 能编译和渲染，但运行时会被提升到 1.12.1。
Compose / serialization主工程显式对齐 Compose 1.12.1、serialization 1.11.0；既有会话、配置、API 和压缩测试通过。
BossTerm / native固定 compose-desktop / core-jvm 1.2.183。显式引入 core 以支持对外类型的编译；排除 BossTerm 固定的 macOS ARM artifact，宿主 currentOs 负责 native 选择。当前仅解析 macOS ARM64 Skiko 0.150.1。
菜单与配置不构造 AI/VCS/shell 安装 provider；验证公开菜单构建函数仅产生复制、粘贴、全选、查找、清屏、清滚屏和打开文件夹。渲染器设置目录在首次初始化前重定向到应用数据目录 terminal/。实际原生菜单为 AWT/Swing，不能通过 Compose 语义树做像素级验收。

2 · 进程清理

TerminalProcessPlatform 包装原生 handle，记录后代身份，关闭时先结束后代与 shell，宽限后强制清理。Unix 补充按 PTY 所属 session 查询成员，覆盖父 shell 立即退出后子进程被重新托管的情况；明确排除宿主应用自身的 session。getsid 接口按 PID 返回 session ID；本机原生测试确认该策略与排除条件实际生效。

Engine、显示层、监听器和 scope 显式关闭，重复关闭等待同一次清理。根 Dispose 与 JVM shutdown hook 共用完成屏障。shell 自然退出后保留最后屏幕，拒绝新输入，只有显式重启才创建下一代进程。

3 · 已接入行为

  • 会话顶部按钮或 Ctrl + 反引号打开；每个 session id 一个终端，从 workspace 启动，首次打开才创建，最多同时运行 8 个。
  • 终端在聊天和右侧信息下方；拖拽分隔线调整比例，小窗口暂时隐藏并保留进程；使用 BossTerm 自己的可见滚动条与滚屏模型。
  • 折叠、切换会话/设置/模型保留进程。关闭、重启、删除会话和完全退出应用清理资源；删除等待期间按稳定 id 定位会话。
  • 工具栏、错误提示和确认弹窗使用 Fluent；恢复会话不抢 Composer 焦点，用户点击后激活。退出后保留输出。
  • Agent run_command、审批、路径边界、JSONL、token 和压缩逻辑保持原样。终端不注册为 Agent 工具，不自动上传输出，不启用安装向导、MCP、分享、daemon、OSC 52 或 Kitty 文件传输。
  • 不注入 Provider 配置凭据，过滤已支持 Provider 的 API Key 环境变量及 OPENAI_API_KEY。错误不直接展示原生环境；链接仅允许用户主动打开 http/https。

5 · 复现与落点

在项目根目录运行：

# 项目回归与 app image
./gradlew test createDistributable createReleaseDistributable

# 原生 PoC、组件测试和自动退出 smoke
./gradlew -p poc/bossterm test uiTest runPoc -PpocSmoke

# 手动独立宿主，不读取 KZAgent Provider 配置
./gradlew -p poc/bossterm runPoc

实现位于 desktop/terminal/ 的 Manager、Handle、ProcessPlatform、UnixSession、SettingsProfile，以及 desktop/ui/SessionTerminalPanel.kt。根生命周期和会话编排位于 DesktopSessionHost / Effects / Conversation / Bindings；poc/bossterm/ 通过 source set 使用同一实现，不维护副本。

6 · 验证边界

  • 实际执行平台为 macOS ARM64。Windows/Linux 的原生启动、键盘、进程清理和安装器仍需对应平台验证；Unix 特定的 HUP/session/UI fixture 在 Windows 上明确跳过，不能算通过。
  • 真实中文输入法、多行粘贴、Ctrl+C 与复制组合键、TUI 备用屏幕、触控板、长时间高输出、长路径悬浮预览及原生菜单定位，尚未完成完整人工矩阵。
  • 本地终端按用户 OS 权限运行；通过自建 session/系统服务刻意脱离终端的进程不构成可靠收容对象，此集成不是进程沙箱。清理失败会报告。
