# 项目（Project）— 产品与实现 Spec

- 状态：首版实现与自动化验证已落地；跨平台真机交互待验收
- 日期：2026-11-25
- 范围：KZAgent 桌面端项目管理、会话归属、历史迁移与目录启动兼容
- 本文件为首版实现依据；实施与验证记录见第 13 节。

## 1. 目标

以持久化的“项目”取代当前按工作区路径临时计算的会话分组。

核心关系：

```text
路径 /repos/app
  ├─ 项目 P1「主线开发」
  │    ├─ 会话 S1
  │    └─ 会话 S2
  └─ 项目 P2「架构研究」
       └─ 会话 S3
```

1. 一个项目绑定一个工作区路径，一个路径可以创建多个项目。
2. 项目具有稳定 ID 和用户可修改的名称；目录名仅用于建议默认名称。
3. 每个可执行的桌面会话必须属于一个存在的项目。
4. 分组、展开状态和项目选择使用项目 ID，不使用名称或路径作为项目身份。
5. 空项目独立存在，不能从会话列表反向推导项目列表。
6. 旧会话自动迁移，保留历史、名称、模型、Todo 和原文件位置。

**项目是组织单位，不是文件隔离或安全隔离单位。** 两个项目使用同一路径时，读写同一批文件；运行时、消息上下文、Todo 和终端仍按会话独立管理。项目名称不自动注入模型提示词。

## 3. 首版范围

### 3.1 必须实现

- 创建项目、自定义名称、重命名项目。
- 同路径多项目、空项目持久化和展示。
- 删除空项目。
- 从项目创建会话，侧栏按项目分组。
- 开始页、会话顶部、提示与辅助功能描述展示真实项目名称。
- 旧会话和旧展开状态迁移。

- 存储失败、损坏引用和失效目录的可见错误处理。

### 3.2 非目标

- 修改已有项目的工作区路径。
- 移动、复制会话到其他项目。
- 删除非空项目、批量删除项目内会话。
- 项目级 Provider、模型、审批、Skills 或 MCP 配置。
- 自动创建 worktree、复制目录、锁定共享目录或隔离文件写入。
- 新增 CLI 项目选择参数；CLI ask/chat 保持原有按目录工作方式。
- 跨进程保存新会话草稿。

这些是首版默认设计取舍，不代表用户已逐项确认。

## 4. 领域模型与不变量

### 4.1 Project

```kotlin
data class Project(
    val id: String,
    val name: String,
    val workspace: Path,
    val createdAt: Instant,
)
```

- `id`：创建时分配 UUID，创建后不变；名称和路径均不得替代 ID。
- `name`：去除首尾空白后非空，禁止换行及控制字符；允许中文、空格和 emoji。
- 同名项目允许存在，选择列表中用路径和短 ID 区分完全同名同路径的条目。
- 不硬性限制短名称；长名称需省略显示，并提供完整文本提示。
- `workspace`：保存绝对、规范化路径，首版创建后不可修改。
- `createdAt`：首次创建时间，不随重命名或迁移重试变化。

### 4.2 会话归属

`StoredSession` 与 `SessionData` 增加 `projectId`。加载旧数据时允许临时缺失，但只有归属有效且路径一致的会话可进入正常执行状态。

会话继续保留不可变的 workspace 快照：

```text
session.projectId -> 存在的 project
workspaceIdentity(session.workspace) == workspaceIdentity(project.workspace)
```

- 创建会话时从项目获取 workspace，不接受可独立指定且不一致的两个值。
- 项目重命名不触碰会话 workspace、消息或 runtime。
- 显式项目引用无效时，不得按路径重新猜测归属。
- 删除最后一个会话不会删除项目。

### 4.3 路径比较

提供统一的项目路径比较函数：绝对路径化、`normalize()`；Windows 使用 `Locale.ROOT` 进行大小写归一，其他平台保留大小写。

此比较仅用于目录匹配、历史归集和一致性检查，不作为项目 ID。首版不额外合并符号链接别名，也不改变现有 `AppDataDir.workspaceKey` 的历史目录定位算法。项目匹配不能替代现有 PathGuard 的真实路径和安全边界检查。

## 5. 持久化格式与失败语义

### 5.1 项目注册表

新增应用数据目录下的 `projects.json`，不保存到工作区或仓库中：

```json
{
  "schemaVersion": 1,
  "projects": [
    {
      "id": "f78b2db6-6699-4c5a-ab83-0205278e7a71",
      "name": "主线开发",
      "workspace": "/repos/app",
      "createdAt": "2026-11-24T16:33:10Z"
    }
  ],
  "legacyDefaults": {
    "/repos/app": "f78b2db6-6699-4c5a-ab83-0205278e7a71"
  }
}
```

- `legacyDefaults` 仅用于没有项目归属的历史或 CLI 会话，禁止用于合并已有项目。
- key 为第 4.3 节定义的路径身份；项目 ID 才是关联值。
- 序列化 schema 应显式管理版本；未知更高版本阻止写入，避免覆写未来数据。
- 注册表不存在表示首次使用；注册表损坏不等于空项目列表。损坏时显示错误、禁止自动覆写和自动重建，允许修复后重试。
- 重复 ID、无效默认映射、非法名称等必须报告，不能任意取第一条继续写入。

### 5.2 会话归属 sidecar

在会话 JSONL 同目录新增 `<session-file>.project`，UTF-8 纯文本保存项目 ID。

- 新会话创建事务包含 JSONL、name、workspace、model 和 project sidecar。
- 任一步失败或创建取消，清理本次新建的文件；成功后才发布会话到内存列表。
- 删除会话同时删除其 project sidecar，不删除项目。
- 不新增 `AgentMessage` 类型，不重写消息 JSONL，不搬动旧会话文件。

### 5.3 展开状态

新增 `session-project-collapses.json`，结构为版本号及 `expandedGroups: Map<projectId, Boolean>`；缺失项默认展开。

旧 `session-group-collapses.json` 保留，不再作为新状态写入目标。只有新项目没有显式展开状态时才导入旧路径状态，不得在每次启动覆盖用户后续选择。

### 5.4 原子性和串行化

- 项目注册表与新展开状态文件使用同目录临时文件写入，再替换目标文件；优先使用原子移动。
- 平台不支持原子移动时，使用可恢复的备份替换方案，不能先截断唯一有效副本。
- 项目增删改和迁移由单一协调入口串行化，防止并发快照覆盖。
- 先持久化，后发布内存状态。失败时保留输入和原状态，展示脱敏错误。
- 多文件迁移不是单一文件系统事务，必须按第 8 节做到可重试，而非宣称全部原子完成。

## 6. 界面与交互

### 6.1 侧栏

```text
创建新会话
新建项目
项目列表
  ▼ 主线开发             [新建会话] [更多]
      修复登录问题
      调整设置页
  ▼ 架构研究             [新建会话] [更多]
      暂无会话
```

- 项目标题展示自定义名称；完整名称和路径可通过提示查看。
- “更多”提供重命名、删除；非空项目删除禁用并说明“请先删除项目内的会话”。
- 项目标题切换展开状态；独立操作按钮不得同时触发展开切换。
- 项目按最近会话更新时间倒序排列，无会话时使用 `createdAt`；相同时间按稳定 ID 排序。
- 项目内沿用会话更新时间倒序规则；重命名项目不改变排序。
- 空项目常驻展示；新建项目后自动展开，并在开始页选中该项目。
- 项目管理入口在窄窗口和折叠导航下仍可访问，不能只依赖悬停按钮。
- 项目名称与路径相关展示使用 Fluent 语义样式，不引入独立 Material 风格区域。

### 6.2 新建项目

使用 Fluent `ContentDialog` 或 `FluentDialog`：

- 字段：项目名称、工作区目录；按钮：创建、取消、选择文件夹。
- 选择目录后建议填入目录名；用户已手动编辑名称时，后续选择目录不得覆盖该名称。
- 根目录没有目录名时，以完整路径作为默认名称。
- 同路径已有项目不阻止创建，可提示“此目录已关联其他项目，文件将共享”。
- 点击创建时重新验证名称、目录存在、为目录且可读。
- 创建过程中锁定重复提交；成功才关闭弹窗，失败保留全部字段。
- 取消不保存项目；明确点击创建后项目立即持久化，即使之后未发送任务。
- 创建项目不创建会话文件或 runtime。

### 6.3 重命名与删除

- 重命名弹窗预填当前名称；校验规则与创建一致。
- 重命名仅更新注册表；侧栏、选择器、顶部和提示应立即同步。
- 允许项目中有运行任务时重命名，不中断任务、不重建 runtime。
- 仅空项目可删除；确认时再次检查项目存在且没有会话引用，避免竞态。
- 删除默认迁移项目时，在同一次注册表写入中清理其 `legacyDefaults` 映射。
- 删除后清理项目展开状态；若清理失败，遗留的无引用 UI 状态不影响删除成功。
- 若草稿选中了被删除项目，保留任务文本等字段，清空项目选择并提示重新选择。
- 删除项目绝不删除工作区目录或其文件。

### 6.4 开始新会话

- “工作区”字段改为“项目”，候选来自项目仓库，包含空项目。
- 每个候选显示名称、路径；完全重名同路径时额外展示短 ID。
- 选择项目后路径只读，另有“新建项目…”入口，不允许直接修改草稿路径后绕过项目归属。
- 项目草稿至少包含 `projectId?`、待处理的启动目录、模型、审批、任务文本、提交状态和错误。
- 项目与目录待选择状态互斥；没有有效项目时禁止发送，并提供明确引导。
- 全局“创建新会话”保留已有未发送草稿；无草稿时优先使用当前会话的项目，否则按启动目录解析。
- 项目行的“新建会话”显式切换草稿所属项目；保留任务文本、模型和审批，并在页面显示当前所选项目。
- 仅在首次有效发送时创建真实会话，继续使用已有统一发送链路。
- 模型与审批语义不变，尤其不能借此次改动将审批变成项目级设置。

### 6.5 会话页与可用性

- 顶部显示项目名称，路径为次要信息；运行状态、模型和终端操作维持现有功能。
- 工具提示和无障碍描述同时包含项目名、会话名、路径和运行状态。
- 长名称、长路径使用省略及完整提示，布局适配窄窗口。
- 所有滚动区域提供可见、可拖拽且共享状态的滚动条。
- 保持 Enter、平台换行组合键和输入法组合输入行为；弹窗焦点和错误提示可由键盘访问。

## 7. 目录启动与单实例转发

普通 GUI 启动仍先显示开始页，不创建空会话。`OpenWorkspace` 请求保留“只更新准备状态，不创建会话”的语义。

| 目录匹配结果 | 行为 |
| --- | --- |
| 一个项目 | 预选该项目 |
| 多个项目 | 进入开始页，显示该目录下的候选项目，要求用户明确选择；不能擅自取最近或第一项 |
| 没有项目 | 显示新建项目引导，预填路径和建议名称；用户确认前不持久化项目 |
| 目录无效 | 显示错误，不覆盖原有效选择和任务文本 |

- 启动目录按第 4.3 节规则匹配项目，历史迁移完成后再解析。
- 已有未发送草稿时保留任务文本、模型和审批；显式目录请求更新项目选择或待选择状态。
- 取消新建或选择时不丢失草稿；未解决目录归属前不允许发送。
- 草稿正在提交时，继续沿用现有忽略目录更新的行为，不改动本次提交快照。
- 普通 `Activate` 仅唤起窗口，保持页面和草稿不变。
- 首版不增加 CLI `--project` 参数，也不因目录转发改变正在运行的会话。

## 8. 历史迁移与 CLI 兼容

### 8.1 加载顺序

1. 读取并校验项目注册表。
2. 扫描既有会话和辅助元数据，包括根目录及旧工作区子目录。
3. 区分：有效项目引用、无归属会话、损坏/悬空引用、无法恢复工作区的会话。
4. 对无归属且路径可恢复的会话执行迁移。
5. 导入尚未具有新状态的旧展开状态。
6. 发布项目和会话视图，再解析启动目录。

加载结果需要携带诊断信息；不能继续通过 `mapNotNull` 将无法归属的数据静默隐藏。

### 8.2 无归属会话迁移算法

对每个规范化路径：

1. 如果 `legacyDefaults[pathKey]` 指向有效且路径匹配的项目，复用该项目。
2. 否则创建一个默认项目，名称使用目录名，并同时写入默认映射。
3. **先持久化注册表及映射，再逐个写会话 project sidecar。**
4. 单个 sidecar 失败时记录诊断，保留未迁移状态；下次重试复用已保存映射，不重复创建项目。
5. 显式 project sidecar 一旦存在，不因同路径出现其他项目而重分配。

注册表写入失败时不写任何会话归属。默认项目可能因中断暂时为空，这是可恢复的合法状态。禁止仅使用全局“迁移已完成”标志跳过后续无归属会话。

### 8.3 旧展开状态

- 用旧规则计算路径状态 key，映射到对应的默认项目 ID。
- 新项目状态不存在时才导入；缺失旧状态默认展开。
- 新状态持久化成功前不删除旧文件，失败可安全重试。
- 后续用户主动创建的同路径项目不继承旧路径状态。

### 8.4 CLI 会话

- CLI ask/chat 保留原有目录、存储和共享运行时行为，不要求选择项目。
- 桌面后续发现 CLI 新产生的无归属会话时，按上述默认映射归档，不按“最近使用项目”猜测归属。
- 若默认项目曾被删除，再遇到新的无归属 CLI 会话，可重新创建一个默认项目并保存新映射。
- 保留旧目录 hash 定位和会话加载兼容，不重命名、不移动 CLI 历史。

### 8.5 异常与不可恢复数据

| 情况 | 处理 |
| --- | --- |
| workspace sidecar 缺失但可通过现有旧目录规则恢复 | 使用恢复出的路径迁移，按现有兼容规则补齐元数据 |
| workspace 无法恢复 | 显示未恢复会话数量、文件标识和原因；不删除、不猜测启动路径、不创建 runtime |
| project sidecar 空白、格式非法或指向不存在的项目 | 显示归属错误；不当作“无归属”自动迁移 |
| 项目路径与会话路径不一致 | 禁止执行，显示一致性错误，不自动改绑 |
| 目录已删除或不可读 | 保留项目与可读历史；禁止新会话和工具执行，明确提示路径不可用 |
| 迁移部分失败 | 有效项目和会话可正常展示；异常条目在诊断区可见，提供重试入口 |
| 注册表损坏或版本不支持 | 阻止项目写入和依赖归属的执行，保留磁盘数据并提示修复后重试 |

首版诊断可采用错误横幅加可展开详情，不将错误条目伪装成普通项目。异常隔离不代表允许自动删除或覆盖损坏引用。

## 9. 运行时与生命周期

- 新增 `startNewSessionInProject(projectId, selection)` 等明确的桌面业务入口。
- 创建时固定项目 ID、workspace、模型和任务快照；不得在异步返回后重新读取活动会话推断所属项目。
- 项目删除与会话创建共享协调锁，消除检查为空后被并发创建会话的竞态。
- 项目没有独立 runtime、线程池或网络客户端；不因项目切换初始化全部会话。
- 同路径多个项目内的会话继续独立创建 runtime 和终端；不复用消息上下文。
- 重命名项目不得关闭 runtime 或终端。
- 会话删除、取消、runtime 失效和应用退出沿用现有显式关闭链路。
- 不削弱路径边界、敏感路径保护、密钥脱敏、命令审批或工作区 AGENTS.md 的加载规则。

首次发送边界：创建前校验失败不留会话；创建后的 runtime 或网络失败留在唯一已创建会话，不返回开始页重复创建。全局配置写入与会话创建仍不是同一事务。

## 10. 建议实现拆分

| 阶段 | 交付内容 |
| --- | --- |
| 1. 模型与仓库 | Project、项目注册表、路径身份函数、原子保存、校验和仓库测试 |
| 2. 会话与迁移 | project sidecar、无归属迁移、诊断结果、旧展开状态导入及 CLI 兼容 |
| 3. 管理与状态 | 项目增删改、按项目新建会话、锁与创建快照、基于 ID 的 UI 状态 |
| 4. UI 与启动 | 项目侧栏、创建/重命名弹窗、开始页、顶部身份、目录启动歧义处理 |

公共模型、存储及迁移逻辑不依赖 Compose；UI 仅负责交互和状态展示。不得复制 CLI 和桌面两套 Agent 执行逻辑。

## 11. 验收标准

| 编号 | 场景 | 必须满足 |
| --- | --- | --- |
| AC-01 | 同路径创建两个项目 | ID 不同、可使用不同名称，重启后仍独立存在和分组 |
| AC-02 | 同名同路径项目 | 可创建、可通过短 ID 区分，选择和操作不串项目 |
| AC-03 | 创建空项目 | 立即持久化并显示；不产生会话 JSONL 或 runtime |
| AC-04 | 项目创建失败/取消/重复点击 | 失败不发布半成品，取消无写入，重复点击只创建一次 |
| AC-05 | 项目重命名 | 名称在全部视图更新，ID、会话、路径、展开状态和运行任务不变 |
| AC-06 | 删除空项目 | 注册表和默认映射正确清理，不删除工作区；草稿文本保留 |
| AC-07 | 非空项目删除与创建竞态 | 禁止删除非空项目，不产生悬空会话引用 |
| AC-08 | 首次发送 | 恰好一个会话，projectId/workspace/model 来自同一提交快照 |
| AC-09 | 首轮请求失败 | 保留唯一会话及既有错误/重试语义，不创建第二个会话 |
| AC-10 | 删除最后一个会话 | 项目仍显示且可重新创建会话 |
| AC-11 | 旧数据首次迁移 | 每个旧路径一个默认项目，消息、名称、模型、Todo 和文件位置不变 |
| AC-12 | 迁移中断与重复启动 | 注册表落盘后任意 sidecar 写入中断，再次加载不重复创建项目、不重分配已归属会话 |
| AC-13 | 迁移后新增同路径项目 | 已有会话归属不变，展开状态彼此独立 |
| AC-14 | CLI 新会话 | 桌面加载时归入明确的默认项目，不归入随机同路径项目 |
| AC-15 | 目录启动零/一/多匹配 | 分别引导创建、预选唯一项目、要求明确选择；发送前不创建会话 |
| AC-16 | 无效目录/损坏引用/未知 schema | 错误可见，不静默丢数据、不自动覆写、不错误启动工具 |
| AC-17 | 注册表或元数据写入失败 | 原有效数据可恢复，错误脱敏，修复后可重试 |
| AC-18 | 展开状态迁移 | 原状态首次继承；之后按项目独立保存，重命名和重启不丢失 |
| AC-19 | 历史恢复及压缩 | JSONL 和 token 读取、上下文压缩后继续对话均无回归 |
| AC-20 | 同路径不同项目运行 | runtime、终端、Todo、上下文独立；明确共享磁盘文件且安全边界不变 |
| AC-21 | 平台与交互 | Windows/macOS/Linux 路径、亮暗主题、窗口缩放、长名称、滚动条、键盘和输入法合理工作 |
