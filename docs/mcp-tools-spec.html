MCP 工具注册与调用

用户注册 MCP Server 后，KZAgent 发现其工具，将工具交给当前模型选择，并通过现有 Agent loop 完成审批、调用和结果回传。CLI 与桌面端使用同一套实现。

推荐方案

采用官方 Java SDK 2.1.0，接入共享运行时；首版提供用户级 Server 注册、stdio / Streamable HTTP、工具启停和连接诊断。以 MCP 2025-11-25 为协议基线，保留现有文字消息与 JSONL 格式，每轮固定工具快照。

注册只保存配置；“测试连接”会实际启动进程或访问服务；启用后的 Server 在会话下一轮开始前连接。MCP Server 属于用户授权的外部程序或服务，其权限由该程序或服务自身决定。

1. 目标与交付范围

这里的“注册 MCP”指向 KZAgent 注册一个 MCP Server，由客户端发现该 Server 的工具；用户无需手写每个工具的 function schema，也无需修改 Kotlin 代码。

首版必须支持具体行为
注册与管理新增、编辑、删除 Server；Server 总开关；按原始工具名称禁用；表单与 mcpServers JSON 导入；用户级配置跨工作区复用。
两种传输stdio 启动本地程序；Streamable HTTP 连接本地或远端端点，兼容其 JSON 与 SSE 响应。
发现和调用协议协商、完整分页发现、schema 转换、名称隔离、审批、tools/call、文字及结构化结果回传。
可用性显示连接状态、实际可用工具数与逐工具不可用原因；单 Server 故障不影响其他 Server 和内置工具；提供测试连接、刷新和重连。
双入口一致桌面端可管理并使用；CLI 可管理、测试并在 chat / ask 中使用。

首版范围外：Server 市场与自动安装、项目仓库配置自动执行、OAuth 登录、旧式 HTTP+SSE 独立端点、MCP resources/prompts 浏览、sampling、elicitation、Tasks、MCP Apps、多模态消息扩展。工具返回的资源链接仍以文字呈现。

2. 接入点与实现约束

MCP 在现有共享工具接口上扩展，以下接口同时服务 CLI 与桌面端。

现有实现对 MCP 的影响
AgentRuntimeFactory.create 合并 Local、Todo、AskUser 与 Skill 工具，通过每轮 prepareTools 回调接入 MCP，创建 CLI / 桌面共享的 CodingAgent。在同一入口合并 MCP registry；连接能力放在共享层。
ToolDefinition 使用 JsonObject 参数 schema 和 suspend handler；ToolResult.content 为字符串。MCP 输入可适配为现有工具；首版输出使用文字封装，保持消息格式。
ToolRegistry 使用名称索引，并在构造时拒绝重复名称。MCP 必须分配独立别名；registry 构造与合并增加重复名称拒绝，防止覆盖内置工具。
CodingAgent.runInternal 每轮准备并冻结工具表，每次请求发送相同 schema，按返回顺序串行执行工具；先扣配额，再执行 handler。沿用执行顺序与每次 1 积分的默认成本；每轮冻结 registry，结果仍跟随对应 Assistant 消息。
requiresApproval 未在 Agent loop 中执行审批。run_command 在 handler 内调用审批策略。仅设置 MCP 工具 requiresApproval=true 不足以生效；MCP handler 必须显式调用审批策略。
ApprovalRequest 包含命令执行、受保护文件读取和 MCP 调用，支持 AUTO / MANUAL / FULL。MCP 调用请求复用终端、桌面弹窗和审批 Agent 的描述分支。
SessionManager 持有每个会话的 runtime；技能变化可在下轮重建；invalidate、删除、退出会关闭 runtime。复用下轮生效的机制；MCP 会话连接由对应 runtime 独占并关闭。
AppDataDir 使用 FileKit 跨平台路径。saveSettings 对技能字段有专门合并逻辑。MCP 使用独立 mcp.json，避免常规设置保存覆盖 Server 注册，也允许缺少模型配置时管理 MCP。
estimateContextTokens 估算消息文本；CodingAgent 在压缩判定与无 usage 的回退估算中额外计入工具 schema。MCP 工具集另有 schema 预算，防止工具定义占满上下文。

3. 协议基线与 SDK 选择

3.1 明确支持哪个协议

截至调研日，官网 latest 指向 2026-07-28，基础协议改为无状态、自包含请求与逐请求能力协商。首版采用 2025-11-25 的 initialize 生命周期：协商版本与能力，发送 initialized，再发现和调用工具。两种生命周期不能混写成同一种实现。

首版验收覆盖 2025-11-25、2025-06-18、2025-03-26，以及 stdio 的 2024-11-05（当前 open-browser-control 使用该版本）；请求优先使用 2025-11-25，仅接受这些已覆盖版本。不兼容时将该 Server 标为“协议不兼容”，保留其他工具。2026-07-28-only Server 暂不可接入；双协议 Server 可协商到上述版本。2024-11-05 只用于 stdio；旧式 HTTP+SSE 不列入首版支持承诺。

3.2 推荐 Java SDK 2.1.0

候选源码证据与取舍结论
官方 Kotlin SDK 0.16.0协程与 kotlinx.serialization 接入自然，但 ToolSchema 根层仅定义 $schema/properties/required/$defs/type，不能无损表示 additionalProperties、根层 oneOf 等约束；其最新协议常量仍是 2025-11-25。暂不采用。不能为方便接入而静默丢弃 schema 约束。类型源码 · 版本常量
官方 Java SDK 2.1.0Tool.inputSchema / outputSchema 使用 Map，可保留完整字段；目标 Java 17。提供异步客户端与 JDK Streamable HTTP transport；代价是引入 Reactor 与 Jackson，并处理协程桥接。采用。schema 保真和现有 JVM 17 比语言一致性更关键。工具类型 · 构建配置
自行实现完整 MCP 客户端需要维护 JSON-RPC、版本协商、分页、HTTP/SSE 与通知处理。不采用；本项目只实现工具适配、进程归属和必要的取消控制。

依赖锁定 io.modelcontextprotocol.sdk:mcp-core:2.1.0、mcp-json-jackson3:2.1.0，显式创建 mapper；增加与现有协程版本一致的 kotlinx-coroutines-reactor。通过 Mono.awaitSingle / awaitSingleOrNull 桥接，不在 UI 线程 block()，不引入 Spring。

HTTP 采用 SDK 的 JDK transport。stdio 采用项目持有 Process 的小型 McpClientTransport：复用 SDK 消息编解码与客户端协议层，只承担行读写、stderr、工作目录和进程关闭。原因是 SDK 内置 stdio 的进程字段私有，优雅关闭会等待进程退出；项目需要可控的强制终止入口。SDK stdio 实现

Java SDK 2.1.0 的 Tool 类型也有明确缺口：没有 execution.taskSupport 字段。连接层必须在 SDK 将 tools/list 结果转换成 Tool 前，从 JSONRPCResponse 的原始 Map 中保留该字段，按原始工具名关联目录；不能把字段被忽略误判为“不要求 Tasks”。这与取消 ID 跟踪共用一个 transport 适配器，不另建协议层。

4. 用户流程与桌面交互

4.1 注册 → 测试 → 启用 → 使用

  1. 进入侧栏“MCP”，选择“添加 Server”，填写 ID、显示名称和传输配置，或粘贴 JSON 导入。
  2. 保存后默认禁用，状态为“未连接”。保存不安装软件、不启动进程、不访问网络。
  3. 点击“测试连接”：本地显示将运行的程序、参数和目录，远端显示端点及将发送的 Header 名称。测试只执行连接、协商、发现，完成后关闭临时连接；不执行任何业务工具。
  4. 工具列表展示名称、描述、参数 schema 和可用性。用户启用 Server，可禁用不需要的工具；新发现工具默认可用，但仍按审批模式处理。
  5. 下一次发送消息前，会话准备 MCP 工具快照。模型根据工具描述选择调用；聊天中展示“Server / 原始工具名”、参数、审批状态和调用结果。

4.2 CLI 接口

kza mcp list
kza mcp add local-search --stdio -- node /path/to/server.mjs
kza mcp add knowledge --http https://mcp.example.com/mcp
kza mcp import /path/to/mcp-config.json
kza mcp test local-search
kza mcp tools local-search
kza mcp enable local-search
kza mcp disable local-search
kza mcp remove local-search

list、add、import、enable、disable、remove 仅访问配置；test 与 tools 会临时连接，结束后关闭。以上命令不要求模型 Provider 已配置。复杂 env、Header、工具筛选通过 JSON 导入或编辑文件设置；不提供把密钥放到 CLI 参数里的专用选项。

CLI chat / ask 每轮开始前读取配置；发现配置变化时重连。运行期间不启动后台文件监视。正常完成返回 0；配置或命令失败返回 1；test 成功但无工具仍返回 0 并明确提示。chat / ask 中的单个 MCP Server 故障只打印诊断，不使整个任务退出。

5. 配置格式与注册语义

路径为 AppDataDir.appDir().resolve("mcp.json")，与模型配置处于同一平台数据目录。文件缺失等同空注册。使用独立 McpConfigStore 读写，临时文件写完后替换目标文件；多个桌面写入口由同一 Mutex 串行化。损坏文件必须报错并保留，不能用空配置覆盖。

{
  "mcpServers": {
    "local-search": {
      "displayName": "项目检索",
      "type": "stdio",
      "enabled": false,
      "command": "node",
      "args": ["/absolute/path/to/server.mjs"],
      "cwd": "${workspace}",
      "env": { "SEARCH_TOKEN": "${env:SEARCH_TOKEN}" },
      "disabledTools": [],
      "connectTimeoutSeconds": 15,
      "callTimeoutSeconds": 60
    },
    "knowledge": {
      "displayName": "团队知识库",
      "type": "streamable_http",
      "enabled": false,
      "url": "https://mcp.example.com/mcp",
      "headers": { "Authorization": "Bearer ${env:KNOWLEDGE_TOKEN}" },
      "disabledTools": ["delete_document"],
      "connectTimeoutSeconds": 15,
      "callTimeoutSeconds": 60
    }
  }
}
字段约定
Server IDJSON key 即稳定 ID，格式 [a-z][a-z0-9-]{0,23}。创建后不能直接改 ID；显示名称可编辑，默认等于 ID。禁用记录与工具别名绑定 ID。
type / enabledtype 必填；enabled 缺省为 false。无配置时没有 MCP 工具。导入的新增条目统一保持禁用；现有条目冲突必须由用户选择替换或跳过，不自动覆盖。
command / argscommand 是单个可执行文件，args 为字符串数组；直接 ProcessBuilder，不拼成 Shell 命令。程序不在 PATH 时使用绝对路径；缺少 Node/Python 等运行环境时报可操作错误。
cwdstdio 专有，默认 ${workspace}；可填绝对路径，启动前验证为现存目录。${workspace} 替换为当前会话工作区；临时测试在页面选择的工作区或 CLI 当前目录运行。
env / headers字符串值支持 ${env:NAME}，在连接时解析；缺失引用使该 Server 不可用，错误只给变量名。stdio 继承宿主环境后覆盖显式 env；HTTP 不自动发送宿主环境，只发送配置 Header。注册前清楚说明该行为。
urlHTTP 专有，必须是完整 MCP 端点，路径和非敏感查询参数原样使用。远端使用 HTTPS，本地 loopback 可用 HTTP；不允许 URL userinfo，不将密钥放入 URL。拒绝跨源重定向携带凭据；协议 Header 由 SDK 管理，用户不可覆盖。
disabledTools按大小写敏感的 Server 原始名称匹配。列表保留已消失工具的禁用偏好，重新出现后仍禁用。
超时connect 默认 15 秒，范围 1–120 秒，覆盖启动/协商/全量发现；call 默认 60 秒，范围 1–3600 秒，只从实际派发开始计时，不含用户审批等待。每个 Server 可调整。

只在 env / headers 值解析环境引用，只有 cwd 支持 workspace 替换；不提供任意模板或 Shell 展开。示例中的路径与域名仅为占位。导入只接受本 spec 字段，逐项报告不支持字段；无 type 的条目可按 command → stdio、url → streamable_http 推断，二者冲突则拒绝。不宣称任意其他客户端配置均可直接兼容。

6.1 组件职责

组件职责与归属
McpConfigStore配置解析、语义校验、注册增删改；不持有连接、不依赖 Provider 配置。
McpRuntime : AutoCloseable每个 AgentRuntime 独占；持有本会话的 Server 连接、工具目录、状态流与配置快照。Server 独立准备，用受监督协程并发，最多 4 个连接任务，避免逐个超时拖长首轮。
McpServerConnection一个 Server 的 SDK 异步客户端、transport、调用锁、状态。单连接一次只派发一个业务调用，符合当前 Agent loop 串行语义。
McpToolAdapter名称映射、schema 保真转换、审批、调用及文字输出裁剪，生成现有 ToolDefinition。
临时测试连接由测试命令或页面操作的作用域持有，使用相同连接实现；结果和错误都在 finally 关闭。离开页面取消测试。

6.2 一轮的工具表保持不变

  1. AgentRuntimeFactory.create 负责本地构造，将 suspend prepareTools 回调交给 CodingAgent.runConversation，在双端每轮入口统一执行 MCP 准备及状态发布，不在 Factory 或 UI 内嵌套 runBlocking。
  2. 准备结束时只将可用且启用的工具合入本轮 registry，按 Server ID、原始工具名排序；CodingAgent.runConversation 从入口捕获快照，整个 loop 的 schema 与 handler 查找引用同一个 registry。
  3. 收到 notifications/tools/list_changed 后只更新待发布目录；本轮不变，下轮重新全量分页发现并发布。手动刷新采用相同路径。
  4. 每轮准备时读取 MCP 配置，与本会话的上一份配置比较；变化后先关闭该会话旧 MCP 连接，再应用新配置。保留模型客户端、历史、压缩摘要与 Todo，无须为 MCP 重建整个 AgentRuntime。
  5. 若本轮 Server 中途断开，工具别名仍留在快照；调用返回“服务已断开”，不会从其他 Server 猜测或替换。下轮自动尝试一次重连；手动重连也可触发。已派发调用不重放。

会话间不共享 MCP 连接与进程。相同 Server 被三个会话使用时会有三个连接，stdio 对应三个进程；这与 cwd、连接状态和关闭归属一致。首版不增加进程池或引用计数管理。

6.3 能力协商

仅使用服务端 tools 能力；提供 roots 时仅返回当前工作区 URI（Path.toUri()），不动态变化。未实现的 sampling / elicitation / tasks 不声明。没有 tools 能力或工具列表为空时，连接状态可成功但显示“无可用工具”。服务端 instructions 不自动追加为系统提示词。

7. 工具适配、上下文与会话记录

7.1 名称与 schema

模型端函数名为 mcp_<serverId>_<toolAlias>，只使用 ASCII 字母、数字、下划线和连字符，最长 64 字符；内部始终保存 (serverId, originalToolName)，调用 Server 时使用原名。原名可直接使用且长度合适时以原名为 alias，否则使用 t1/t2/…。

别名按原名排序后分配，先预留可直接使用的名称，再分配数字别名；冲突时递增编号。映射在 runtime 内保留，消失工具的 alias 不复用，防止目录刷新后误路由。恢复会话不根据旧 alias 重放工具，新的工具调用只查当前映射。聊天显示 Server 名与原名，历史正文携带同样来源信息。

inputSchema 通过 SDK mapper 转成 JSON，再解析为 kotlinx JsonObject，保持嵌套 schema、required、enum、additionalProperties、$defs/$ref 与组合约束。客户端只校验 schema 为 object 且根 type 为 object；无 type 时补 object，显式非 object 则禁用该工具。参数 JSON 必须为 object；完整参数校验由 Server 执行。

不通过删除约束来兼容模型 Provider。Provider 拒绝某 schema 时显示请求错误和 MCP 来源，用户可禁用相关工具；实现阶段必须验证三个内置 Provider 的实际 schema 接受范围。需要 Tasks 的工具不可用；taskSupport=optional 时使用普通同步调用。

7.2 输出归一化

MCP 结果传入 ToolResult.content 的形式
text按 Server 顺序保留文本；首行标注 [MCP server=… tool=…]。
structuredContent独立的“structuredContent”JSON 区块，与 text 均保留，不把业务 JSON 拆成指令。
resource_link / 嵌入文本资源输出标题、URI、MIME；嵌入文本可作为文本输出。不自动访问链接或调用 resources/read。
image / audio / blob输出类型、MIME 和“此内容尚未展示”的标记；不把 Base64 放进模型上下文或 JSONL。只有这些内容时返回“结果包含暂不支持的内容”，并标 isError=true。
isError=true映射 ToolResult.isError=true，保留裁剪后的业务错误文本。协议错误、连接错误也转成工具错误，附本地分类与是否已派发。

归一化结果上限默认 20,000 字符，超出部分在区块边界优先裁剪；标明原始长度与省略内容，避免半截 JSON 被当作完整 JSON。结构化块无法完整容纳时省略该整块并标明，而不是生成无效 JSON。结果不提供 readPaths：外部 Server 的文件读取不能冒充经过 PathGuard 的本地读取。

首版不新增 AgentMessage 类型。归一化文本及 isError 沿用现有 Tool 消息、JSONL、Markdown 展示、压缩和恢复路径；调用详情显示来源。压缩摘要保留 Server/原名和结果的业务含义。恢复只恢复对话记录，不保存连接 ID、Header、env 或远端会话凭据。

7.3 schema 预算与缓存稳定性

给 MCP 工具 schema 设置每轮最多 min(16,000, contextWindowSize × 10%) 的估算 token 预算，使用与当前文本估算一致的字符近似法。内置工具预算独立计入上下文开销；MCP 目录超预算时，整个 MCP 工具集本轮不注入，桌面/CLI 明确给出原因和按 Server 的估算用量，让用户禁用工具后重试；不静默截断 schema 或任选前 N 个工具。

工具 schema 估算纳入开始前的自动压缩判定与无 usage 时的回退估算；Provider 返回的 prompt/total usage 已含 schema，不重复相加。压缩只能减少历史，不把 schema 超预算反复转成压缩循环。

Server 顺序、工具顺序和 schema 序列化保持确定性；正常轮次不往基础系统提示与历史之间插入连接状态。需要告诉模型某个启用 Server 不可用时，通过现有动态提示位置放在本轮最后 User 前，并避免拆开 Assistant/tool-results。目录变化只在下轮改变工具前缀，接受这次必要的缓存失效。

8. 审批与权限

增加 ApprovalRequest.McpToolCall，包含工作区、Server ID、端点或可执行文件摘要、原始工具名、脱敏参数、描述和 annotations。MCP handler 在真正调用前使用现有 ModeApprovalPolicy；拒绝时返回错误工具结果，Server 不收到 tools/call。

现有模式MCP 行为
MANUAL每次业务调用向用户审批；明确显示 Server、工具和脱敏参数。
AUTO调用审批 Agent 判断；无法判断则交给用户。不要把 MCP 调用套进命令静态白名单。审批 Agent 的提示词从“local operation”扩展为包含外部工具及其副作用。
FULL延续现有完全放行语义。仍尊重 Server 启用和工具禁用配置。

readOnlyHint / destructiveHint / idempotentHint 只作为显示与判断参考，不单独触发免审批或重试；这是 Tools 规范 对 annotations 的约束。测试连接、启用 Server 是用户在管理入口直接发起的操作，不依赖模型审批 Agent。

注册界面明确说明：stdio 是以当前用户身份运行的外部进程，cwd 与 roots 不是操作系统沙箱；远端 Server 仅收到连接元数据与工具调用参数，不自动收到整段聊天。保留内置 PathGuard、敏感路径保护与命令审批；MCP 不能声称受同样文件边界保护。

密钥通过 env 引用配置为主；界面按 Header/env 字段遮罩。诊断默认只记录 Server、工具、耗时、结果分类与退出码，不记录原始 Header、env、请求/响应全文。现有 SecretRedactor 主要识别特定 key/Bearer 模式，不能覆盖任意 MCP token；MCP 连接作用域额外收集已解析的凭据值，在审批显示、异常、stderr、工具输出与 JSONL 写入前替换。运行环境和模型凭据不复制到配置示例或日志。

9. 超时、取消、故障与资源生命周期

9.1 失败如何影响任务

情况确定行为
文件损坏 / 单条配置不合法文件损坏使 MCP 配置不可用并显示错误，内置工具仍可使用；能独立解析的无效条目按 Server 隔离，不阻断其他条目。禁止自动覆盖损坏文件。
程序找不到 / 启动超时 / stdout 非协议文本该 Server 连接失败，清理已启动进程和协程；提示 command/PATH、退出码或协议输出问题，stderr 仅显示脱敏短摘要。
分页发现失败 / 同 Server 重名工具不发布半份目录；保留旧目录时显示“刷新失败，下轮需重连”，不可误报刷新成功。单工具 schema 无效则只禁用该工具并说明原因。
HTTP 401 / 403标记需要凭据或无权限；保留配置与错误码，不打开浏览器做 OAuth，不自动循环登录。
HTTP Session 失效 / 404关闭当前连接；标记待重连，下一轮重新初始化。正在执行的调用结果标为未知，不重放。
Server 返回业务错误 / JSON-RPC 错误生成 isError 工具结果并让模型决定下一步；不自动重试业务调用。
call 超时 / 用户停止 / 连接中断记录“已派发，完成情况未知”或“未派发”；尝试发送取消通知，结束本地等待并使连接失效。超时或中断不等于 Server 已撤销副作用。

9.2 取消不是取消订阅就结束

Java SDK 2.1.0 的 McpClientSession.sendRequest 不能直接证明协程取消会发送协议取消通知。增加薄的 McpCallTrackingTransport，记录当前 tools/call 的 request ID 与是否已发送；在响应结束后清空。它也关联 tools/list 的请求与原始分页响应，保留 execution 元数据；发现失败时丢弃本次未完成目录。业务调用串行，因此无需另建通用任务调度系统。

协程取消或 deadline 触发时，在有界清理作用域向该 ID 发送 notifications/cancelled（最多等待 1 秒），随后关闭并丢弃此连接，清掉 SDK 待响应状态；不得只取消 Mono 而继续复用连接。initialize 不发送取消通知，直接释放连接。取消后重新抛出 CancellationException，不将用户停止转换为普通成功。

补齐本次 Assistant 已发起但尚无结果的工具消息：没有业务结果的调用统一标注中断、完成情况未确认，并持久化后结束轮次；进程异常退出后的会话恢复同样补齐未配对调用，明确不重放。这样下一轮与 JSONL 恢复不会留下孤立的 tool_calls。

9.3 谁创建，谁关闭

  • AgentRuntime.close() 先阻止新调用、取消 MCP 等待，再关闭所有 MCP 连接，最后关闭模型客户端。单项关闭失败继续清理其余资源；关闭幂等。
  • 项目 stdio transport 持有 Process、流与专属 IO executor：先关闭 stdin，等待最多 2 秒；未退出则 destroy，再等 1 秒；仍未退出则对本次进程及其可枚举子进程 destroyForcibly；关闭 stdout/stderr、停止 executor。stdio stderr 必须单独持续消费，不能合并进 stdout。
  • 在 Windows 直接支持可执行程序；.cmd/.bat 需要显式配置 cmd.exe 参数，编辑器提供提示。macOS 桌面 PATH 可能与登录终端不同，错误提示可执行文件绝对路径；不启动登录 Shell 猜环境。
  • HTTP 连接关闭时释放订阅、SSE 与请求；自建 executor 由连接持有并 shutdown。JVM 17 下不假定 JDK HttpClient 可 AutoCloseable，不添加悬空后台线程。
  • runtime 删除、切换、失效、窗口退出、CLI use 结束以及 Factory 部分构造失败都必须覆盖 MCP 清理。异步清理在 IO 调度器执行；同步 close 使用有界等待，不能在 Compose 主线程无限阻塞。

10.2 产品验收标准

  1. 全新用户通过桌面或 CLI 注册一个本地、一个远端 Server；测试显示工具列表；启用后，现有模型能选中 MCP 工具并基于返回内容回答。
  2. 手动拒绝一次调用，Server 观测不到对应 tools/call；停用一个工具后下一轮 schema 中消失；内置工具仍正常。
  3. 一个 Server 连不上时，另一个 Server 和本地工具仍可完成任务；错误来源在桌面与 CLI 均清晰。
  4. 长调用中停止，界面结束等待；下一轮可继续；结果未知明确记录，Server 调用次数不因客户端自动重试增加。
  5. 关窗、退出 CLI、删除会话和临时测试结束后，本次拥有的进程及 executor 均结束；安装包进程正常退出。
  6. 重新打开会话能读取历史 MCP 结果并继续对话；自动压缩保留完整调用配对，无凭据落入日志或 JSONL。

11. Limitations

  • 本机 macOS / JVM 17 已通过完整 297 项测试。当前 Codex 注册的 open-browser-control 已添加并启用，协商 2024-11-05，发现 18 个工具；受控模型经 CodingAgent 读取真实浏览器页面信息，DOM 返回预期内容，测试会话已确认没有残留标签页。优化后的 Release 产物也已完成相同 Server 的实际连接与工具发现。HTTP JSON/SSE 路径由受控服务验证；尚未完成真实 Provider 自主选工具、Windows/Linux 运行与三平台桌面人工交互验收。
  • 首版是 MCP 工具客户端，支持有界同步调用与文字结果；2026-07-28-only、OAuth-only、Tasks-required、依赖 sampling/elicitation 的工具，以及多模态结果的完整消费不在首版能力范围。
  • 外部 MCP 程序可以自行访问文件与网络；应用层审批、cwd 和 roots 不提供操作系统沙箱。密钥引用依赖启动 KZAgent 的环境，桌面启动时未必包含终端 export 的变量。
  • 工具很多时需要用户禁用一部分以满足 schema 预算。首版直接注入启用工具，不提供工具搜索、延迟发现或自动筛选。
  • stdio 每会话启动一份进程；同一账户/设备只允许单连接的 Server 可能拒绝并发会话，应在管理页显示该 Server 错误。取消不能保证远端业务回滚。
  • 配置文件被外部 CLI/编辑器同时修改时，用户应先刷新再保存；首版不增加跨进程实时配置同步。受管理的桌面写入口内部串行。
