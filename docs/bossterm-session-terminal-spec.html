BossTerm 会话底部终端面板

在会话页面提供可折叠、可调整高度的本地交互终端。用户可在对话同时运行测试、查看 Git 状态和使用交互式命令；终端归属于当前会话，并以该会话工作区作为初始目录。

推荐方案：BossTerm 嵌入组件 + KZAgent 自有会话终端管理层。

首版每个会话一个终端，首次展开才启动；折叠和切换会话保留进程及屏幕缓冲；关闭终端、删除会话和退出应用负责清理。Agent 的 run_command 继续采用共享运行时的现有审批与执行流程。正式接入前必须通过版本兼容、内置菜单裁剪、生命周期和三平台打包四道验证门槛。

实施更新：本机 PoC 后选择公开 ProperTerminal + TerminalSessionEngine 路线，已接入会话面板；原高层组件未通过菜单和清理门槛。详见 PoC 验证记录。以下矩阵仍是完整要求，未执行项不能视为通过。

01 · 已核对的实现与上游能力

已查证本地仓库基线 c6a2b9bb163b6bdfb8ef08f43893655796028ff5；BossTerm 上游基线 722965cc39e8492e06c08bde2116f5ea84a33418。本次只读源码、发布元数据和官方文档，未采信性能宣传作为验收指标。

项目现状接入意义
gradle/libs.versions.toml：Kotlin 2.4.0、Compose 1.11.1、JVM 17、Fluent v0.1.0、JNA 5.19.1、serialization 1.9.0。JVM 和 JNA 与当前 BossTerm 发布一致；Kotlin、Compose、serialization 需要单独验证。
DesktopConversation.kt 当前为 Header 下方的 Row：左侧消息列表与 Composer，右侧 SessionSidePanel。底部终端应加在会话内容区域，不侵入全局导航或新建会话页面；消息和输入框始终可达。
SessionManager 以 session id 管理会话；切模型和 invalidate 会关闭并重建 AgentRuntime；删除和 close 负责关闭 runtime。终端不能附着在 AgentRuntime 上，否则切模型或审批会误杀 shell。终端生命周期需要自己的 owner。
LocalTools.run_command 经 ApprovalPolicy 后使用 ProcessBuilder；Unix 为 /bin/sh -lc，Windows 为 cmd.exe /c，有超时和取消清理。现有工具是一次性命令执行，不是交互式 PTY；首版与用户终端并存，不能假装输出来自同一进程。

BossTerm 可用 API 与真实限制

官方入口是 EmbeddableTerminal 与 EmbeddableTerminalState，支持工作目录、环境覆盖、输出/退出/就绪回调和链接处理；状态对象保存终端会话，dispose() 释放资源。rememberEmbeddableTerminalState 默认自动释放，跨折叠保留需要外部所有权。初始化由 composable 驱动，不能把创建 state 等同于已经启动 shell。[B1 源码]

Maven Central 当前最新 desktop 版本为 1.2.183，元数据更新时间为 2026-10-10；本次下载其 sources JAR，确认 EmbeddableTerminal.kt 与上述上游基线 SHA-256 一致。此核对仅覆盖该文件，不代表整个源码树与发布包完全一致。[B2 版本元数据] [B3 发布源码]

不能直接照搬默认配置
  • 1.2.183 POM 声明 Kotlin 2.4.20、Compose 1.12.1、serialization 1.11.0，并包含 MCP/Ktor/分享相关依赖；需要评估解析冲突和安装包体积。[B4 POM]
  • aiAssistantsEnabled=false 可隐藏 AI 菜单，但源码仍追加 VCS 和 shell 定制菜单；添加 contextMenuItems 不会替换这些内置项。自带安装弹窗使用 Material 组件。必须验证可裁剪性，不能假定配置一个开关就能获得干净的 Fluent 面板。[B1 菜单实现]
  • 显式传入 settings 可绕开默认 settings 的解析来源，但组件仍引用 SettingsManager.instance，需检查单例初始化及 shell integration 是否读写 BossTerm 的全局目录。[B5 SettingsLoader]
  • 上游 engine 的关闭包含独立 kill 线程；普通 dispose() 不能直接被当作“整个进程树已清理完成”的证明。disposeForUnload() 有等待语义和调用线程约束，需要实测正常退出与启动中退出。[B6 Engine]

02 · 首版范围与默认决策

首版必须具备后续独立定义
每个会话一个本地终端；工作区初始目录；展开/折叠；拖拽调高；输入、选中、复制粘贴、可拖拽滚动条；退出状态与重启；会话切换保持进程；删除/应用退出清理；亮暗主题。多标签或 split panes；SSH 配置；跨应用重启复活 shell；Agent 读写 PTY；一键转发输出到模型；运行 Agent 工具的统一终端；MCP、分享、远程控制、后台 daemon。

同一工作区内的不同会话拥有不同 shell、cwd 和环境，不按 workspace 共用终端。新建会话准备页、设置页、Skills 页没有终端入口；历史会话首次展开时启动一个全新的 shell。默认只保留本进程内状态，应用重启后全部终端回到未启动状态。

建议资源上限为同时存活 8 个终端，达到上限时阻止新启动并提示关闭已有终端；不自动淘汰运行中的后台 shell。滚屏缓冲建议上限 10,000 行，使用锁定版本实际支持的 buffer 字段；压力测试需同时覆盖极长行和控制序列，不能把行数上限当作内存字节上限。

04 · 用户行为合同

动作 / 情况规定行为
首次展开捕获 session id、workspace、shell 配置快照；校验工作区存在且可访问；进入 Starting；只启动一个 PTY。失败保留会话，终端区域展示错误与重试入口。
重复点击展开 / 重组同一 id + generation 只初始化一次；不重复启动 shell，不重复注册监听器。
折叠 / 打开设置 / 新建准备页只移除显示；shell、解析和有限缓冲继续工作。重新展开不重新启动，不重复运行初始化命令。
切换 A → B → A恢复 A 的终端、cwd、屏幕缓冲和滚动位置；B 按自己的状态显示。后台输出和迟到事件始终写入各自 owner。
shell 自然退出保留最后屏幕，展示 Exited + 可用退出码，停止输入；提供“重启终端”。不自动复活、不循环重试。退出码未知时明确显示未知。
关闭 / 重启运行中的终端Fluent ContentDialog 提示会结束其中进程；确认后停止接收输入、清理后回到 NotCreated，或为显式重启建立下一代 handle。任何 Connected shell 都需提示，不能依靠“看起来空闲”判断无进程。
删除会话已有删除确认说明终端进程会一并结束；确认后清理终端和 Agent 资源。不再加第二个确认。删除失败时保留会话并报告终端是否已关闭。
切模型、改审批 / runtime invalidateshell 保持运行；只有 AgentRuntime 重建。聊天停止按钮只取消 Agent 回合；终端 Ctrl+C 只发给终端前台程序。
退出应用统一停止接入新操作，逐一关闭 PTY，等待有限清理，必要时强制结束其进程树。上游 daemon 关闭，不跨应用退出保留进程。

键盘、焦点与粘贴

  • 建议 Ctrl+` 切换终端（平台可达性需实测），按钮始终保留为替代入口；命中切换动作后消费事件，避免反引号进入 shell。首版不抢占 shell 常用的 Ctrl+L、Ctrl+D、Ctrl+C 或聊天发送快捷键。
  • 用户主动展开后才聚焦终端；会话切换、背景回调、主题切换不能自动抢走 Composer 焦点。折叠时焦点返回 Composer；终端父容器不得通过 focusable/clickable 竞争输入焦点。[B7 焦点说明]
  • 终端有焦点时 Enter、Tab、方向键和控制键交给终端；macOS Cmd+C/V 为复制粘贴，Windows/Linux Ctrl+Shift+C/V 为复制粘贴，Ctrl+C 保持中断语义。具体映射以锁定版本可配置 API 与实测为准。
  • 中文输入法组合过程中 Enter 只确认候选词；不同时触发聊天发送或全局动作。多行粘贴保留 bracketed paste 语义，宿主不追加换行、不给输入补上隐式执行。

05 · 架构与状态模型

DesktopSessionHost / 根生命周期→SessionTerminalManager→BossTermTerminalHandle→BossTerm State / PTY

SessionTerminalPanel 只依赖终端状态和用户动作。新增类型名为设计建议，尚未实现。Manager 是桌面能力，持有 Map<SessionId, TerminalHandle> 和独立于可见面板的 scope，实现 AutoCloseable；适配器封装 BossTerm 类型，避免把第三方 state 塞入 SessionData、AgentRuntime 或 AgentMessage。

TerminalUiState: sessionId, visible, heightRatio,
                 phase, shellLabel, title, exitCode?, redactedError?
TerminalPhase: NotCreated → Starting → Running → Exited / Failed
                                       ↓
                                    Closing → NotCreated

TerminalHandle: sessionId, generation, immutable LaunchSpec,
                thirdPartyState, ownedScope, idempotent close()
LaunchSpec: initialWorkspace: Path, shellExecutable, environment policy
Manager actions: ensureHandle(sessionId, spec), setVisible(), restart(),
                 closeSession(sessionId), closeAll()

首次挂载由 EmbeddableTerminal 驱动初始化，Manager 的 ensureHandle 只保证 owner 和去重；不要宣称可直接调用内部 initializeSession。Manager 不能使用会随面板消失而取消的 rememberCoroutineScope。所有跨线程事件在 UI owner 线程更新 Compose 状态；事件包含 session id + generation，过期代次和已删除会话的事件丢弃。

适配器只需向宿主提供显示状态、终端重启和关闭；首版不对 Agent 暴露 write/sendInput。上游 onExit/输出回调应捕获稳定 handle，不能闭包读取 activeSession()。onTitleChange 当前由 composable 中的 Flow 收集，隐藏时不能承诺持续刷新标题；首版允许恢复显示后补齐标题。

公开组件没有独立的 onError 参数，内部 connectionState 也不能直接当公开 API 读取。PoC 必须确认 PTY 启动失败如何映射到宿主 Failed 状态；必要时补小型公开适配接口，不能通过反射访问 internal，也不能仅凭“等了一段时间”报告失败。

接入路线选择

优先用高层 EmbeddableTerminal，复用解析、渲染、输入、滚屏和 resize。若无法关闭多余安装菜单、避免全局设置副作用或取得必要错误/关闭信号，优先向上游添加少量宿主配置与生命周期接口；期间可用锁定基线的最小补丁构建验证。只有这个路线无法满足约束时才评估 ProperTerminal + 自有 session 层；低层方案需显式承担字体、IME、菜单、连接和关闭编排，不进入首版默认范围。

06 · 生命周期与恢复规则

边界资源责任
UI 重组、隐藏、切页state 保留在根 Manager 的 handle 中。传入外部 state，不启用面板级 autoDispose；保持后台解析，避免未读取 PTY 输出阻塞子进程。
关闭 / 重启进入 Closing 后拒绝新输入；取消 UI 收集，关闭 PTY 和 I/O，再取消 owner scope。重启必须等待上一代停止，防止两个 shell 同时持有同一终端。
删除会话在会话列表移除前按稳定 session id 关闭 handle；不使用可能因删除而变化的 activeSessionIndex。资源关闭与 repository 删除不是事务，失败文案需反映实际结果。
根 composable Dispose / 应用关闭DesktopSessionEffects 串联 Manager 关闭。每个 handle 独立兜底，一个失败不能阻止其他资源关闭。终止等待与 JVM 退出顺序需协调 DesktopAppHost，避免提前 System.exit。
应用重启 / JSONL 恢复恢复聊天照旧；终端不恢复 PID、cwd、输出和旧命令。首次展开从 session.workspace 新开 shell。不写终端 I/O 到 JSONL，不新增消息类型。

关闭目标：每个进程先请求结束，超过建议 2 秒宽限后强制清理；全局退出建议总预算 5 秒，具体值由三平台实测确定。等待不应长期阻塞 UI owner 线程。上游 disposeForUnload 需在 UI owner 线程且不在终端回调内调用；若其等待方式不满足退出 UX，需要适配层暴露异步关闭/等待能力。不能把“cancel coroutine”或“移除 state 引用”当作 PTY/进程树已经终止。

首版不落盘终端状态；不修改会话 JSONL/schema，不改变历史恢复、上下文压缩和 token 估算。若以后需跨启动恢复面板布局，只存独立 UI 偏好，仍不得保存并自动重放命令。

07 · Shell、目录与平台行为

平台推荐启动策略与验证
macOS / Linux使用有效且可执行的 SHELL，失败回退可用 /bin/bash 或 /bin/sh。交互 / login 参数按锁定上游 resolveSessionCommand 验证，避免自行把可执行文件路径和用户参数拼成字符串。特别验证 macOS Finder 启动时 PATH 与命令行启动差异。
Windows首版跟随 BossTerm 的 PowerShell 默认和 cmd 回退；其现有设置值为 powershell/cmd，不能假定 pwsh 已可用。验证 ConPTY、中文输出、路径空格、驱动器根目录和窗口 resize；PTY 不可用时明确报错，不降级成伪交互 ProcessBuilder 面板。
所有平台通过 workingDirectory 传入 session.workspace.toString()，目录处理使用 Path；不先注入 cd 字符串。shell 内自行 cd 不修改 Agent 的工作区，也不切换应用会话；关闭后重开回到初始工作区。

环境继承系统运行环境，保留常规 PATH/locale/TERM 需求；不从 AppConfig 向 shell 注入 Provider 凭据，不打印整个 environment。若宿主进程环境含已配置的 Provider 凭据变量，应建立不泄密的过滤策略；不能声称本地 shell 是沙箱或无法访问用户自己的环境/文件。

首版不配置 initialCommand。需验证上游 shell integration 注入是否写入 shell 配置、自动安装工具或修改长期用户设置；KZAgent 应只允许进程内或其自有受控目录中的临时集成。shell 路径含空格、权限不足、workspace 被删除和原生库加载失败均进入 Failed，可修正后显式重试。

08 · 用户终端与 Agent 的权限边界

用户在终端直接输入的命令按本地用户 OS 权限运行。终端初始目录并不构成工作区沙箱，用户可以 cd 到其他位置。面板不展示权限与初始目录说明；不能用 Agent 审批模式标签暗示手动终端已受同样限制。

  • Agent 的 run_command、路径保护、敏感路径策略、审批、超时、脱敏和 CLI 共享逻辑完整保留。聊天工具输出留在原消息展示，终端不显示伪造的“同进程执行”。
  • 不启动 BossTerm MCP manager、session sharing、relay 或 daemon；明确设置 mcpEnabled、mcpAutoAttachInstalled、daemonEnabled、sessionSharingEnabled 为 false，并检查嵌入路径确实不监听端口、不自动附着外部工具。
  • 关闭 aiAssistantsEnabled、fileLoggingEnabled 和默认命令完成通知；默认禁用 OSC 52 clipboard 访问，普通用户快捷键复制粘贴仍可用。VCS/shell 安装菜单需裁剪，不能通过内置 Material 安装向导执行额外流程。
  • 终端原始屏幕用于用户查看；应用错误、诊断和持久化日志仍经 SecretRedactor。终端输出不自动上传模型、写入 JSONL、参与 token 计算或上下文压缩。未来“发送选区给 Agent”必须有明确动作、预览与脱敏规格。
  • 链接点击通过 onLinkClick 白名单处理 http/https；文件路径复用工作区边界和敏感路径判断。拒绝未知 scheme 时应返回已处理，避免落回默认系统打开；后台 OSC 发起的打开请求也遵守相同策略。

未来若让 Agent 控制 PTY，需新 spec 定义独立批准、输入仲裁、cwd 与 env、取消/超时、输出截断和审计；不能将 state.write 直接注册为新工具绕过现有机制。

12 · 实施顺序与进入条件

  1. 可行性 PoC。独立小 Compose 宿主验证 1.2.183 依赖/variant、公开 API、启动失败信号、隐藏继续运行、resize、内置菜单裁剪、配置副作用和 await shutdown；三平台打包抽样验证。产出最终坐标、依赖树、所需升级/补丁和许可证记录。
  2. 管理层与生命周期。先完成假终端测试和终止协议，再加入真实适配器；确认切 runtime 不影响终端。
  3. Fluent 会话面板。接 Header、上下布局、焦点、分隔线、错误/重启/关闭及删除编排；保留原聊天链路。
  4. 验收与说明。完成 A01–A12，更新 README 和平台验证记录。只有阻塞项解决才将功能作为可用入口交付。
评审时重点确认

当前建议是“每会话单终端 + 首次展开启动 + 进程内保留 + Agent 不控制 PTY”。实现前仍需落定：是否接受 Kotlin/Compose 升级、是否维护最小上游补丁，以及资源上限和退出预算是否需要调整。这些不影响本 spec 的调研结论，但影响最终依赖和发布安排。
