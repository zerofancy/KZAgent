开始新会话

应用启动和“创建新会话”入口先进入准备页面。用户选择工作区、模型、审批方式并输入任务，首次点击发送后，才创建并进入真实会话。

核心约束

打开页面、切换选项、选择目录或输入文字，都不创建会话记录、JSONL 文件或会话 runtime。历史会话仍可直接打开。首次有效发送只创建一个会话，并使用页面中确认的配置执行第一轮任务。

1. 范围与已确认的现状

本次仅定义桌面端的开始页面、导航及首次发送流程；CLI chat 的使用方式和共享 Agent 行为不变。本文件为实现 spec，不包含业务代码修改。

当前实现本次变化
SessionManager.loadOrCreate 在指定启动创建时生成会话；无历史记录时也生成“新会话 1”。初始化只加载历史会话，允许列表为空；全新桌面进程默认显示开始页面。
addNewSession、startNewSessionInWorkspace 立即调用 repository.create。新建入口和工作区启动请求只设置页面草稿；首次发送才调用创建方法。
会话模型保存在 model sidecar；切换模型同时更新全局默认模型。页面先暂存模型，首次发送成功创建时保存会话模型并更新后续新会话默认。
DesktopSessionSettingsState.onApprovalModeChanged 写入全局配置并使 runtime 失效。保持全局审批语义；页面选择先暂存，提交时应用。明确展示“全局设置，提交后对所有会话生效”。
deleteSession 禁止删除最后一个会话；页面把空列表作为加载状态。允许删除最后一个会话，删除后显示开始页面；区分加载中、加载失败和成功但无历史会话。

  • 工作区列表取已加载会话的工作区，按规范化 Path 去重，按最近会话顺序排列。显示目录名称和完整路径，重名目录可区分。当前草稿的新选目录立即可选，但不单独持久化工作区历史。
  • “打开文件夹…”复用 FileKit 目录选择器。取消不改变任何字段；选择后验证目录存在、为目录且可读。无效路径显示就地错误并保留原选择。
  • 普通启动默认工作区为启动传入的 initialWorkspace；“创建新会话”默认采用当前会话工作区，无当前会话时用 initialWorkspace。模型和审批默认取最新已保存配置。
  • 模型复用现有 ModelSelector / 模型目录服务。目录加载失败可展示错误及重试；仍允许使用已配置有效默认模型，不因可选模型列表请求失败阻断发送。Provider 缺失或配置不可用则要求打开设置。
  • 输入支持多行和现有平台键盘约定。空白内容不能发送。发送中锁定本次草稿的字段和发送动作，避免重复提交；输入法候选确认不得误触发送。
  • 缺少模型配置时显示配置引导，允许选择工作区和输入任务；完成设置返回原草稿。设置保存失败不丢失输入。
  • 页面主体自适应窗口，输入区使用 heightIn；所有溢出区域，包括目录列表和多行输入，提供共享状态的可拖拽滚动条。长路径和模型名不挤出发送按钮。

3. 导航与草稿规则

触发结果
全新桌面进程启动，包括已有历史会话加载历史记录，进入开始页；不自动创建或运行会话。
点击“创建新会话”进入开始页。已有未发送草稿时继续该草稿；无草稿时按当前会话工作区初始化。
从开始页选择历史会话，再返回开始页打开历史会话；保留本进程内草稿的工作区、模型、审批和输入。
打开 / 关闭设置或 Skills 页面返回先前页面，不隐式创建会话或清空草稿。配置变更后重新验证草稿模型，失效时提示重新选择。
已运行实例收到 Activate（普通再次打开应用）仅唤起窗口，保留当前页面和草稿。
已运行实例收到 OpenWorkspace（如 kagent app）唤起并进入开始页，将草稿工作区改为请求目录；保留已输入文字及其他选择，不创建会话。无效目录不覆盖原草稿。
删除最后一个会话关闭被删除会话资源，进入开始页，不生成替代会话。
关闭应用 / 首次成功创建草稿不跨进程保存；成功创建后消费该草稿，下一次新建从最新默认配置初始化。

4. 状态与首次发送边界

导航显式区分 NewSession、Session(id)、设置等页面，不能用会话列表索引或空列表推导当前页面。草稿至少包含 workspace、modelSelection、approvalMode、input、提交状态和错误信息，不含持久化 session id。

  1. 发送时立即锁定提交状态，获取草稿快照；校验非空任务、目录可读、Provider 配置和模型选择有效。失败留在开始页，保留全部输入，不创建文件。
  2. 若审批方式变化，完成配置保存并按现有生命周期规则关闭旧 runtime；不得取消运行中的历史任务来隐式应用新审批方式。存在忙碌会话时，仍允许使用当前审批方式发送；若草稿试图改变全局审批方式，则阻止该次提交并说明需等待任务结束或选回当前方式。
  3. 创建会话时显式传入工作区和模型快照，不读取可能变化的 activeSession 或 defaultModel。repository 创建必须在文件或元数据写入失败时清理本次残留，创建成功后才发布到会话列表。
  4. 创建成功后立即进入该会话，将首次任务交给与历史会话相同的发送流程：runtime 初始化、用户消息、标题生成、历史恢复、runConversation、token 和状态更新。避免复制一套 Agent 执行逻辑。
  5. 防止自动初始化 effect 与首次发送竞争，复用 runtimeMutex 保证单个 runtime；busy/currentJob 在导航前正确设置。切到其他页面不取消已经提交的任务。
  6. 仅在任务已交给会话发送流程后消费草稿。首轮 runtime 初始化或模型请求失败时保留已创建会话和任务内容，展示现有失败 / 重试行为；不得返回开始页并再次创建第二个会话。进程异常中断的恢复继续遵循已有会话持久化边界，不能宣称首轮未写入的输入已经保存。

“首次发送才创建”指接受有效发送动作后创建，并不要求模型响应成功后才创建。创建前的失败不留会话；创建后的网络失败属于真实会话失败。全局配置写入与会话文件创建不是同一事务：若配置已保存但会话创建失败，已保存配置仍有效，页面明确报告创建失败并允许重试。

5. 实现落点与兼容性

  • desktop/app/DesktopSessionHost.kt：页面路由、草稿生命周期、入口重定向、首次提交编排和共享发送回调。仅会话页面驱动活动会话的自动 runtime 初始化，停留开始页不为历史会话启动 runtime。
  • desktop/session/SessionManager.kt：初始化加载但不创建；安全支持空列表和 nullable 活动会话；新建接收显式模型；删除最后一条后无活动会话。更新所有 activeSession 调用点，避免索引越界。
  • desktop/session/SessionRepository.kt：创建残留清理；复用现有 workspace / model sidecar 和 JSONL，不引入新的 AgentMessage 类型。
  • desktop/ui：新增开始页，复用工作区选择、模型选项和审批选项语义；新控件优先 Fluent。导航删除动作需要去掉“至少保留一个会话”的 UI 限制。
  • DesktopSessionSettings.kt：提供无 SessionData 依赖的默认模型提交路径；审批保存需报告完成或错误，不能使用直接跳回其他页面的旧 onDismiss 行为。
  • Main.kt、DesktopAppHost.kt、DesktopSingleInstance.kt：把 createStartupSession 的语义调整为打开开始页 / 工作区意图，建议重命名以消除“启动即创建”的误导；保留单实例转发协议兼容或同步升级协议测试。
  • 共享运行时、审批安全规则、路径边界、上下文压缩和旧会话读取保持兼容；不迁移或删除既有空白会话。网络资源继续通过 SessionManager / DisposableEffect 显式关闭。
  • 实现时同步更新 README 桌面启动、工作区切换及新建会话说明。

6. 验收与验证

场景验收标准
首次启动 / 有历史启动均显示开始页；加载完成不新增会话文件，不创建会话 runtime；历史列表正确显示。
反复点击新建、改模型、审批、选目录、输入会话数量不变；发送前不持久化草稿选项，不创建 runtime；离开再返回输入完整。
首次有效发送 / 连续 Enter 或双击恰好一个会话、一次用户提交；工作区和模型与快照一致，审批按约定应用；首条内容只出现一次，标题仍自动生成。
空白输入、失效目录、缺失 Provider、配置写入失败不创建会话，错误可见，草稿可修正后再次发送。
创建写入部分失败 / 取消未发布半成品，无本次残留文件；解除提交锁，不遗失草稿。
创建后 runtime 或网络失败留在唯一已创建会话，错误和任务内容可见；重试不创建第二个会话。
历史任务仍运行、返回开始页任务继续；修改全局审批后提交有明确阻断，选回当前审批可以正常提交。
删除最后一条 / 单实例打开路径安全进入开始页；目录请求只更新草稿，不新增记录；普通 Activate 保持当前页面。
会话恢复、模型 sidecar、压缩后继续对话旧格式正常读取；首次提交采用共享发送链路，不破坏历史恢复、token 和压缩逻辑。
Windows / macOS / Linux，亮暗主题及窗口缩放目录选择可取消；长名称清晰；滚动条可拖拽；Enter、平台组合键、多行和输入法行为正确。

单元测试覆盖草稿状态转换、校验、重复提交保护、空列表、明确配置的创建和失败恢复。扩展 SessionManagerTest、DesktopSessionCallbacksTest、启动参数 / 单实例相关测试，保留已有会话读取与上下文压缩回归。实现完成后在 Linux / macOS 运行 ./gradlew test，Windows 运行 .\gradlew.bat test；UI 做上述平台交互核验。

7. 本 spec 的默认决策

本版本采用：每次全新桌面启动显示开始页；草稿只在进程内保留；已有工作区从历史会话派生；审批维持全局设置并明确标注。若后续希望审批按会话独立保存，需另行定义元数据、旧会话回退和 runtime 配置优先级，不能仅修改选择器外观。
